# Frontend (`frontend/`)

React 19 + TypeScript 7 (strict) + MUI 9, Swiper (library carousel), Chart.js via react-chartjs-2 (statistics). Built with **Vite**, tested with **Vitest**. One public page, Russian only.

## Structure (`src/`)
| Path | Role |
|---|---|
| `App.tsx` | MUI theme (Merriweather, primary `#212529`, secondary `#4ECCA3`) + `AuthProvider` + `BooksProvider` + `HomePage` |
| `components/<name>/` | One folder per UI block: `<name>.tsx`, and as needed `.hooks.ts` (state + handlers), `.styles.ts` (MUI `styled`/sx), `.constants.ts`, `index.ts` (default export). Re-exported from `components/index.ts` |
| `context/auth-context.tsx` | `user` (from `me()` on mount; `null` = logged out), `isAdmin`, `login()`, `logout()`, `sessionExpired()` (forget the user after a 401 on a write) |
| `context/books-context.tsx` | Loads **all** books once; derives `newBooks`, `currentBook` (first `progress`), `finishedBooks` (sorted by rating desc); `refreshBooks()` refetches after a write |
| `services/api.ts` | `ApiService` over `fetch`, plus function exports the components use. JSON bodies get `Content-Type: application/json`; a `FormData` body (`uploadCover`) gets none, so the browser sets the multipart boundary. Every non-GET request copies the `XSRF-TOKEN` cookie into header `X-XSRF-TOKEN` (`CSRF_COOKIE` / `CSRF_HEADER`); the session cookie goes along by itself (same-origin `fetch`). Non-2xx → `ApiError` (`status`, ProblemDetail `detail`); empty body → `undefined`. `login()`, `logout()`; `me()` → the user, or `null` on 401 |
| `routes.ts` | `API_ROUTES`, every backend URL (relative `/api/...`) |
| `i18n.ts` + `locales/ru.json` | Own `t('dotted.key', params)` helper; put UI text in `ru.json` |
| `types/index.ts` | `Book`, DTOs, `Statistics`; mirrors the backend contract in [architecture.md](architecture.md) |
| `utils/use-full-screen-dialog.ts` | `useFullScreenDialog()`: `true` below MUI `sm`. The selection, random-book, statistics, add and edit dialogs pass it as `fullScreen`; login and approval stay small |
| `utils/cover.ts` | `coverSrc(book)`: `image?v=<updatedAt>`, or `cover-placeholder.svg` (in `public/`) for a book without `image`. Use it wherever a cover is rendered. The `?v=` is needed: a re-uploaded cover can keep its name, and an upload changes `updatedAt`, so the page loads the new image without a reload. Also `COVER_TYPE` / `COVER_MAX_BYTES` (JPEG, 2 MB, as the backend) and `CoverUploadError` |
| `test/` | Vitest setup (`setup.ts`: jest-dom, MSW server lifecycle, `matchMedia` stub), MSW `server.ts` (default `GET /api/books`), fixture `books.ts` |

Page order: current book (the page's only `h1`) → library swiper → finished books; the nav items follow it. Main flows: library swiper of all books (filtered by a search over title / author / tag, case- and «ё»-insensitive, and status chips «Все / В списке / Читаем / Прочитаны»; «Ничего не найдено» when empty) → selection dialog (`new` books; search by tag / title / author, checkboxes, random pick) → random-result dialog → approval dialog → refresh. Statistics dialog toggles count / average rating per tag; it is `React.lazy` in `home-page.tsx` and mounts on the first open (`statisticsDialogMounted`), so Chart.js is a separate chunk. Finished books show 10 at a time with «Показать ещё» (`PAGE_SIZE`). Descriptions in the current book (8 lines) and finished books (5) go through `expandable-text`: clamped, with «Читать дальше» / «Свернуть» only when the text is cut off (measured `scrollHeight > clientHeight`, again on resize and after the web font loads). `back-to-top`: a «Наверх» `Fab` bottom-right, shown after scrolling 600px (`useScrollTrigger`). The legacy feature list is in [legacy-analysis.md](legacy-analysis.md); results of the parity check are in [migration/04-frontend-vite.md](migration/04-frontend-vite.md).

**Account menu:** an icon button at the right edge of the app bar at every width (aria-label «Аккаунт», or «Аккаунт <username>» when logged in), opening an MUI `Menu`. Logged out: only «Войти», which opens `login-dialog` (username + password, a form so Enter submits; a 401 shows «Неверный логин или пароль»). Logged in: the username (disabled item), for an admin the «Режим редактирования» switch (`menuitemcheckbox`, toggles without closing the menu), and «Выйти». There is no login item in the nav or the drawer, and no «Контакты» button (removed 2026-11-01).

**Who sees what:** «Выбор книги» (nav) and the current-book «Выбрать книгу» show whenever `isAdmin`. **«Добавить книгу» and the edit pencils show only in edit mode** (`editing = isAdmin && editMode` in `home-page.hooks.ts`). Edit mode is off on load and turns off whenever `isAdmin` becomes false (logout, `sessionExpired()`), so every login starts with it off; it isn't persisted. Hidden actions are passed to the components as `undefined` props (`onOpenBookSelection` / `onOpenAddBook` / `onSelectClick` / `onEdit` / `onToggleEditMode`). Browsing and statistics stay public.

**Approval dialog:** asks for the current book's rating (required, 1–10, comma or dot); no password. Confirm → `finishBook` → `startBook`, then `refreshBooks()` (also after a failure, since finish may have succeeded). A 401 (the session is gone) shows «Сессия истекла. Войдите снова.», and `home-page.hooks.ts` calls `sessionExpired()`, which hides selection. Any other error shows a generic message. The hook (`approval-dialog.hooks.ts`) picks the message from the error type.

**Cover drop zone** (`cover-drop-zone`, in both book dialogs): a dashed box (`role=button`, aria-label = the hint text) that takes a dropped file, or a click / Enter / Space opens a hidden `<input type=file accept=image/jpeg>` (aria-label «Файл обложки»). It rejects non-JPEG («Нужен файл JPEG») and > 2 MB («Файл больше 2 МБ») before `onChange`; the preview is an object URL (revoked on change). «Убрать выбранный файл» clears the choice, back to `currentSrc` (the book's cover in edit). The dialogs only hold the chosen `File`; the upload happens on submit.

**Add-book dialog** (`add-book-dialog`, from «Добавить книгу»): title, author, tag («Участник», MUI `Autocomplete freeSolo` with the distinct tags from all books as suggestions), description (`wiki`, multiline), optional cover (drop zone). Text fields required and not blank, the same rules as the backend; on submit it highlights blank fields with «Заполните все поля» and makes no call. Values are sent trimmed; `home-page.hooks.ts` calls `addBook`, then `uploadCover` with the new id if a cover was chosen, then `refreshBooks()` and closes. If only the upload fails, `home-page.hooks.ts` refreshes (the book exists) and throws `CoverUploadError`: the dialog says «Книга добавлена, но обложку загрузить не удалось…» and disables «Добавить», so the book isn't added twice. 401 → «Сессия истекла…» + `sessionExpired()`, as in the approval dialog; any other error → generic message.

**Edit-book dialog** (`edit-book-dialog`): opened by the pencil (`edit-book-button`, aria-label «Изменить «title»»; edit mode only) on the library swiper cards (top-right corner of the cover), the current book and the finished books. `home-page.hooks.ts` holds `editingBook` (`null` = closed). Same fields as add (it reuses the `dialogs.addBook.*` labels and the add-dialog styles) plus «Статус» (select) and «Оценка», shown only for «Прочитана» and required 1–10 there (`parseRating` from the approval dialog). The values are sent trimmed as a full `BookDto`, with no `rating` unless finished. «Удалить» switches the actions to an inline confirmation («Да, удалить» / «Нет»), with no browser `confirm()`. A cover drop zone shows the current cover; a newly chosen file is uploaded after the edit is saved (no upload when none was chosen). After a save or delete: `refreshBooks()` and close. 401 → «Сессия истекла…» + `sessionExpired()`; 409 → «Уже есть текущая книга…»; a failed upload after a saved edit → `CoverUploadError`, refresh, «Изменения сохранены, но обложку загрузить не удалось…» (submitting again re-sends the edit, which is harmless); otherwise a generic message. A 401 on the upload stays an `ApiError` (session expired), not a `CoverUploadError`.

## Layout notes
- **Library swiper:** always horizontal, `slidesPerView: 'auto'` with the card width set in CSS per breakpoint (`CARD_WIDTH` 140 / 170 / 190 px), so the next card peeks out on phones; `FreeMode` + `Keyboard` + `Navigation`. The arrows (MUI `IconButton`s bound by class) show from `md` up only. `loop` only with more than 8 books: Swiper's loop with `'auto'` needs more slides than fit on screen. The `.swiper` element has `minWidth: 0` (a flex child), or it widens the page on phones. Covers are `loading="lazy"`. The swiper is keyed by filter + search + loop, so a new filter starts at the first book and loop on/off gets a fresh swiper. A status chip on the cover (bottom-left): «Читаем», or «Прочитана · <rating>»; none for `new`.
- **Navbar offset:** `home-page.styles.ts` `contentBoxStyles` has the top padding that clears the fixed navbar, so it works whichever section comes first.
- **Phones:** section headings 2rem on `xs`; covers in the current and finished books are 60% wide on `xs` with `aspectRatio: 2 / 3` (no fixed heights). Checked for no sideways scroll at 320 / 360 / 390 / 768px.
- **Navbar:** desktop nav from MUI `lg` (1200px) up, hamburger below. The desktop nav needs ~1150px, so at `md` it squeezed the title. The desktop title has `flexShrink: 0`; the mobile title is 0.9rem on `xs` and wraps on the narrowest phones.
- **Anchors:** all three sections have `scrollMarginTop: 48px`, so a nav click lands the heading below the fixed navbar (up to 93px tall on desktop). Keep it if the navbar or section spacing changes.

## Dev setup
- `vite.config.ts` proxies `/api` and `/images` (covers from GridFS) → `http://localhost:8080`. Covers in dev need the backend running and covers in the local Mongo's GridFS (the compose data has them; a fresh volume gets them from a dump, see [architecture.md](architecture.md)). `vite build` doesn't include covers.
- `index.html` lives in `frontend/` (Vite entry); `public/` holds `manifest.json`, `robots.txt` and `cover-placeholder.svg`.

## Tests
Vitest + React Testing Library + MSW 3, jsdom. Test files sit next to the code (`*.test.ts(x)`); `App.test.tsx` drives the full flows through MSW.
- Auth in `App.test.tsx`: `renderApp({ loggedIn })` installs `mockAuth` (`me` / `login` / `logout` handlers sharing one fake session; login `admin` / `secret`) and waits for the account button named «Аккаунт» or «Аккаунт <username>», so the auth state is settled. Helpers `openAccountMenu`, `clickMenuItem(user, 'Войти' | 'Выйти')` and `toggleEditMode` (switch in the menu, then Escape); the add and edit tests turn edit mode on first. A test sets `document.cookie = 'XSRF-TOKEN=…'` to check the CSRF header. An open MUI dialog makes the rest of the page `aria-hidden`, so query the app bar behind it with `{ hidden: true }`.
- MSW 3: the strict option is `onUnhandledFrame: 'error'` (v2's `onUnhandledRequest` is silently ignored). Import `http`, `HttpResponse` from `msw`, `setupServer` from `msw/node`. Add write handlers per test with `server.use(...)`.
- **Uploads:** jsdom's `File`/`FormData` don't survive Node's `fetch` (undici sends an empty part named `blob`, and MSW's `request.formData()` throws). So the App-level MSW cover handler checks only path, CSRF and the multipart content type, and `api.test.ts` spies on `fetch` to check the `FormData` holds the file. Pick a file with `user.upload(getByLabelText('Файл обложки'), file)`; drop with `fireEvent.drop(zone, { dataTransfer: { files: [file] } })`. `URL.createObjectURL` exists (Node's) and returns `blob:nodedata:…`.
- jsdom has no canvas: `statistics-dialog.test.tsx` mocks `react-chartjs-2`'s `Bar` to print labels and values; `App.test.tsx` mocks it as an empty `<output data-testid="chart">`.
- jsdom has no layout (every height is 0), so «Читать дальше» never shows unless a test spies on `HTMLElement.prototype` `scrollHeight` / `clientHeight`. The «Наверх» test sets `window.pageYOffset` and fires `scroll`; restore it afterwards.
- jsdom is pinned to 29: jsdom 30 needs Node ≥ 24.15, the dev machine has 24.14.

## Known gaps
- Starting a book with no book in progress goes through the approval dialog with no fields (just confirm). The club never does this (there's always a current book), so it's untested in the browser.
- Confirm in the selection dialog is **disabled** with 0 books checked; the legacy page showed an error modal «Добавьте книжки для выбора» instead. The `noSelectedError` text is unused.
- Unused `ru.json` keys from before Phase 4: `bookSelection.selectBookButton`, `bookSelection.closeButton`, `bookSelection.confirmMessage`, `randomBook.anotherButton`.
- Main JS chunk ~690 kB (MUI + Swiper + React) after splitting off the statistics dialog (~165 kB with Chart.js); Vite still warns about chunk size.

## Commands
Run from `frontend/`: `npm install`, `npm run dev` (Vite dev server, `http://localhost:5173`), `npm run build` (`tsc --noEmit` + `vite build` → `dist/`), `npm test` (Vitest once), `npm run test:watch`, `npm run preview`.
